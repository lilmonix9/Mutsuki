# 0003 · 软件渲染截图测试

- 日期：2026-11-25
- 状态：采用

## 选了什么

- **Mesa lavapipe（CPU 上的 Vulkan）+ Xvfb**，跑真实的 Forward+ 渲染器。脚本检查日志里的设备名包含 llvmpipe，防止悄悄换成别的设备或渲染器。
- **测的是导出后的 Linux 版**，不是编辑器，和用户拿到的一致。启动参数 `-- --screenshot-dir=<目录>` 进入截图模式：相机依次放到固定机位、隐藏 HUD、等 30 帧后截图、退出。机位在 `app/scripts/screenshot_runner.gd`。
- **两类检查**（`app/tests/compare_images.gd`）：
  1. 语义检查：不依赖基准图，只看区域平均色（天空、地面、白色方块、红色标尺）。防止基准图本身是坏的，或画面整片黑屏。
  2. 基准图比对：任一通道差值 > 24 的像素算「不同」，占比 > 0.5% 即失败，并输出差异图（洋红色标出不同像素）。
- **基准图在 Ubuntu 24.04 + Mesa 25.2.8 上生成**，与 CI 的 ubuntu-24.04 一致。同机连续两次渲染差异为 0%。
- 截图、差异图和渲染日志作为 Actions artifact `screenshots` 上传，失败时也上传。

## 验证过的事

- 故意喂一张全黑图：4 项语义检查全部失败，差异 100%。
- 故意把机位换错：语义检查通过（天空、地面都在），但基准图差异 56%，失败。

## 放弃了什么

- Godot 的 Movie Maker 模式（`--write-movie`）：能截图，但不方便按机位命名、隐藏 HUD。
- 只用 OpenGL/llvmpipe 跑兼容渲染器：当前产品用的是 Forward+，测别的渲染器没有意义。核显最终选哪种渲染器由性能实验决定，届时再加对应的截图测试。
- 第三方图片比对库：GDScript 几十行就够，少一个依赖。

## 局限

- 软件渲染只能证明「画得出、画得对」，不能证明真实显卡上的表现与帧率（项目书第 2 节）。
- 阈值是第一版经验值；以后若因 Mesa 升级等出现细微差异，先看差异图再决定，不能为了通过而放宽或更新基准图。
